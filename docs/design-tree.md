# 设计决策树

日期：2026-10-04。记录已明确选择、待用户决策项以及待核查事实；待定事项不视为已批准方案。

## 已明确的上层选择

- 用户与目标：尚无选品方向的新卖家 → 判断是否值得试卖 → 优先降低试错损失。
- 使用方式：个人使用 → 本地浏览器网页 → 月运行费不超过 100 元。
- 发现方式：有方向直接输入条件；无方向先问答 → 每次在线寻找候选 → 接受部分平台覆盖。
- 证据与成本：需求证据和社交热度分开 → 缺项保留并等待补充 → 不设置统一盈利门槛。
- 资金与供货：总预算档位 1,000～5,000 元 → 首轮试卖投入上限总预算 50% → 代发和小批量均评估。

## 本轮可决策的问题

1. **候选粒度**：推荐商品类型/款式并列出证据链接，还是以具体店铺商品链接为核心？
2. **销售平台**：检索来源覆盖多个平台，但试卖成本是否按用户选定的一个销售平台计算？尚未选定销售平台时怎样展示费用？
3. **预算边界**：总预算是否包含开店固定费用、保证金等资金占用？50% 上限与剩余可用资金怎样同时约束方案？
4. **利润边界**：单件利润是否主要比较订单收入与每单变动成本？固定支出、退款损耗和人工时间分别如何体现？

## 已进行文档核查、仍待实测的事实

- 各代表性平台公开页面、搜索引擎可检索材料与授权接口实际能提供什么。
- 数据来源能否支持具体商品、需求与竞争材料，并记录统计口径与时间。
- 仅有某种接口需要授权不能证明整个来源不可检索；逐条记录约束范围。

代表性官方资料已整理至 [数据可行性记录](data-feasibility.md)，真实检索覆盖、接口准入、预算与字段稳定性仍未实测。

数据事实尚未明确，因此暂不要求用户选择具体接口服务或开发技术栈。

## 等待上游决策的后续分支

- 候选粒度 → 同类归组、不同规格与不同供货方案的比较边界。
- 销售平台与利润边界 → 费用输入项、公式、缺项行为。
- 预算边界 → 投入上限规则与具体验收用例。
- 数据事实 → 具体来源、搜索服务、AI 服务、费用限额、搜索超时和失败策略。
