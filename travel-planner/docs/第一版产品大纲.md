# 国内旅游规划产品 · 第一版大纲

> **本文已降级为背景资料。** 第一版实现依据为[《旅游规划产品总需求文档.md》](旅游规划产品总需求文档.md)；两份文件冲突时以总需求文档为准。本文保留 2026-10-10 形成第一版范围时的原始取舍记录，其中第 3 节（浏览器保存、备份与恢复）与第 5 节（特色、美食与行程联动）对应的规则已从总需求文档中删除，此处仅作历史留存。

版本：1.0  
更新日期：2026-10-10（北京时间）  
范围：六个主要模块，并纳入用户接受的第 1、2、4 项修改。本文不再作为实现依据；需求确认不表示相关网页功能已经实现。

## 1. 产品定位与统一要求

- 面向个人自由行、情侣朋友结伴、亲子家庭，先覆盖国内旅游。
- 网页优先，适配手机与电脑，采用蓝色风格。
- 不同功能按钮使用对应图案并保留文字；同一操作保持一致图标。
- 参考信息显示来源与适用时间；缺失或冲突时标记“待核实”。
- 第一版仅整理购买金额、外部购买链接和购买记录，不包含付款、收款、转账、代付、退款办理、结算或分账功能。

## 2. 六个主要功能模块

| 模块 | 第一版包含的功能 |
| --- | --- |
| 我的旅行 | 创建、保存、编辑、删除旅行；设置目的地、日期、同行者、预算和偏好；支持国内多城市旅行 |
| 目的地特色 | 城市概览与具体地方介绍；人文、自然景观、钓鱼、地理特色等；显示来源，支持收藏、选择日期和时段加入行程 |
| 城市美食 | 独立页面；菜系、代表菜、小吃、商圈和店铺；按餐段、口味与忌口筛选；展示参考价格和外部购买、预约链接，选择日期和时段加入行程 |
| 行程安排 | 手动安排每日景点、用餐、住宿和交通；调整顺序、锁定安排、填写备注；保存地址，提供外部地图导航；支持旅行复用 |
| 购买信息与费用 | 手动记录项目名称、日期、数量、金额、购买链接和备注；明确区分预算金额、参考价格与实际购买金额，汇总预算和实际费用 |
| 出行准备 | 同行者口味、忌口与亲子需求；行李和准备清单；预约时间、天气查询链接、住宿地址、应急联系人；支持行程导出 |

## 3. 已接受修改一：浏览器保存、备份与恢复

- 第一版数据保存在当前设备、当前浏览器中，刷新页面后保留已成功保存的内容。
- 显示保存结果；保存失败时明确提示，保留当前输入，不显示虚假的“已保存”。
- 提供完整数据备份导出与恢复导入。备份包括旅行、行程、同行者资料、收藏、购买记录、预算和准备清单；注明备份时间与格式版本。
- 完整备份文件用于恢复数据；行程导出文件用于随身查看，两者在界面上分别命名。
- 换设备或浏览器后，通过手动导入备份恢复；不承诺自动跨设备同步。
- 导入前展示备份时间、旅行数量和覆盖范围，用户确认后恢复。第一版采用整份备份恢复，不实现自动合并。
- 备份损坏或格式不支持时提示失败，并保留现有数据。
- 提示浏览器数据被清理后需要用备份恢复；备份文件需由用户自行保留。

## 4. 已接受修改二：三种金额与计算规则

| 金额类型 | 定义 | 计算方式 |
| --- | --- | --- |
| 预算金额 | 用户计划用于此次旅行的金额 | 作为费用对照，不计为实际购买 |
| 参考价格 | 查询或手动填写的预计购买价格 | 单独展示来源、时间和估算状态，不自动计入实际费用 |
| 实际购买金额 | 用户在外部购买后手动登记的金额 | 纳入实际费用汇总；用户填写不代表网站核验了外部交易 |

- 金额以人民币元记录；每条购买记录中的参考价格与实际购买金额均按该项目总价填写。数量单独记录，不再将已填写的总价重复乘以数量。
- 实际购买金额未填写时保持为空，不用参考价格替代，也不把未知金额写成零。
- 点击购买链接不会自动写入实际购买金额。
- 同一条记录填写了参考价格和实际购买金额时，实际费用只统计实际购买金额一次。
- 与行程关联的购买记录采用同一份金额数据，避免因同时出现在行程与购买信息页面而重复累计。
- 显示旅行总预算、已记录实际费用及两者差额；实际金额未补齐时注明“费用记录未完整”。
- 修改金额后重新计算汇总，支持按交通、住宿、门票、餐饮、租车及其他分类查看。

## 5. 已接受修改四：特色、美食与行程联动

- 在目的地特色或城市美食页点击“加入行程”，选择目标旅行、日期和时段，并核对地点名称、地址和备注。
- 预填已有的地点、地址、参考价格、来源和外部链接，避免重复输入；未查到的信息保持为空或待核实。
- 早餐、午餐、晚餐等餐段用于帮助选择时间，用户可以自行调整，不默认已有预约。
- 只有背景介绍的文化或地理条目，先选择明确的体验地点或活动后再加入行程。
- 加入前检查该安排是否与已有时间重叠；发现冲突时列出冲突项目，并允许修改时间或放弃加入。
- 涉及已锁定安排时，不自动移动或替换原安排。
- 加入后的项目可在行程中编辑、排序、锁定或移除；引用来源与外部链接保留。
- 加入行程不代表已经购买、预约或产生实际费用。
- 第一版仅检查加入时的时间重叠；自动交通计算、全行程复杂冲突检查属于后续范围。

## 6. 后续功能

后续再增加 AI 规划、多方案比较、历史版本恢复、截图/PDF 订单识别、网站内地图与路线计算、多人账户协作、跨设备同步、后台通知、离线缓存及照片游记管理。

本轮仅接受第 1、2、4 项修改；购买记录状态、限制第一批城市、全行程基础时间检查及第五模块改名，仍为未接受的建议，不作为本轮新增要求。

## 7. 第一版主要流程

创建旅行 → 查看特色与美食 → 选择日期和时段加入行程 → 手动调整安排 → 记录参考价格、实际购买金额和外部链接 → 准备出行 → 保存、导出行程及数据备份。

## 8. 实现时的核对示例

1. 新建旅行并保存，刷新后内容仍可查看；导出备份，在另一浏览器导入后可恢复。
2. 某酒店参考价格为 600 元，实际购买金额为 580 元，实际费用只计 580 元；未填写实际金额时不计入实际费用，并提示记录未完整。
3. 从城市美食页将一家店加入指定旅行的午餐时段，自动带入地点和参考链接；与已有活动重叠时提示，不自动覆盖已有安排。

以上为实现要求与核对示例，尚不代表实际功能测试通过。
