## 1. 产品概览

| 项目 | 当前要求 |
| --- | --- |
| 产品用途 | 帮助用户了解目的地、安排行程、整理费用与出行准备，并查看汇总后的完整旅行计划 |
| 目标用户 | 个人自由行、情侣朋友结伴、亲子家庭；由用户个人建设 |
| 地域范围 | 先覆盖中国大陆，支持多城市、异地出发和异地返程 |
| 产品形式 | 网页优先，蓝色风格，手机优先，兼容电脑 |
| 第一版范围 | 六个规划模块（我的旅行、目的地特色、城市美食、行程安排、购买信息与费用、出行准备）、支持 PDF 导出的完整旅行计划汇总页，以及真实登录和注册 |
| 数据保存 | 旅行资料按账户保存在当前设备、当前浏览器；认证账户保存在 PostgreSQL；第一版不做旅行资料云同步、备份与恢复导入；完整旅行计划可由用户主动导出为本地 PDF |
| 外部数据来源 | 店铺地点数据及第一版全部地图能力（地图展示、地点搜索/定位、路径规划、导航）统一使用高德开放平台；不存储、不缓存高德返回数据 |
| 购买边界 | 记录金额与外部链接；不包含付款、收款、转账、代付、退款办理、结算或分账 |
| 当前状态 | 文档记载已有本地演示原型；真实登录注册和其他第一版功能尚未完成，网站尚未正式上线 |

**范围依据：** 第一版以本文为唯一实现依据。历史规划和取舍仅作背景，不作为第一版开发清单；与本文冲突时，一律以本文为准。

国内覆盖是设计范围，不表示每个城市已有完整资料。数据缺失时保留空状态或“待核实”。

## 2. 第一版功能范围

每个模块统一按用途、功能与边界说明。

### 2.1 我的旅行

- **用途：** 管理每次旅行及其基本条件。
- **功能：** 创建、保存、编辑、删除旅行；设置目的地、日期、同行者、预算和偏好；支持国内多城市旅行。
- **边界：** 同行者资料用于规划，不等于已实现成员账户、共享权限或多人协作。

### 2.2 目的地特色

- **用途：** 了解城市和具体地方，选择感兴趣的体验。
- **功能：** 城市概览、具体地方详情；人文、自然景观、美食、钓鱼、地理特色等可扩展分类；可切换当前浏览城市，并收藏、查看来源和地图；页面中的地图底图、地点/POI搜索与定位均使用高德开放平台。
- **内容：** 背景、体验地点、适合季节、所需时间、参考费用和注意事项；美食分类进入独立城市美食页面。
- **切换规则：** 城市选择控制本页当前浏览内容；选项包含本次旅行目的地及可浏览城市。切换后同步更新列表和高德地图搜索城市，不修改旅行目的地或已排行程。
- **边界：** 本页只用于了解和收藏，不提供加入行程。钓鱼地点的准入、开放与预约条件需有来源，无法确认时标记“待核实”。

### 2.3 城市美食

- **用途：** 了解当地风味，选择和安排用餐体验。
- **功能：** 独立页面展示菜系、代表菜、小吃、区域或商圈及店铺；可切换当前浏览城市；按早餐、午餐、晚餐、夜宵、小吃组织；按口味、忌口和亲子条件筛选。
- **内容：** 地点、地址、营业时间、参考价格、候餐及预约信息、外部链接；店铺地点数据和地图搜索由高德开放平台提供，支持收藏和查看高德地图。
- **切换规则：** 城市选择控制本页展示的美食内容和高德地图搜索城市参数；切换仅改变浏览城市，不修改旅行目的地或行程。所选城市暂无资料时显示空状态。
- **边界：** 文化介绍与店铺当前信息分开；店铺信息来自高德开放平台实时查询，营业时间和价格注明来源与适用时间。

### 2.4 行程安排

- **用途：** 手动组织每日活动。
- **功能：** 安排景点、用餐、住宿和交通；调整顺序、锁定安排、填写备注；保存地址，按当天顺序显示高德计算的路线、距离与时长，并跳转高德地图导航；支持旅行复用。
- **边界：** 第一版行程内容由用户手动安排，特色页和美食页不提供加入行程，也不做时间重叠检查。路线、距离与时长来自高德路径规划，地点地图查询和导航也使用高德服务；不自动调整顺序；全行程复杂冲突检查、AI 调整和历史版本恢复属于后续规划。

### 2.5 购买信息与费用

- **用途：** 整理外部购买信息，对照预算与实际费用。
- **功能：** 手动记录项目名称、日期、数量、参考价格、实际购买金额、购买链接和备注；按交通、住宿、门票、餐饮、租车及其他分类查看和汇总。
- **边界：** 不提供产品内交易或分账；用户登记不代表网站已核验外部交易。计算规则见第 4.2 节。

### 2.6 出行准备

- **用途：** 集中查看出发前需要准备和核对的内容。
- **功能：** 同行者口味、忌口及亲子需求；行李和准备清单；预约时间、天气查询链接、住宿地址、应急联系人。
- **边界：** 第一版提供天气查询链接；真实天气接入、后台通知及离线缓存属于后续规划。

### 2.7 完整旅行计划（汇总页）

- **用途：** 在规划完成后，将一趟旅行的关键信息汇集到一个可查看的页面，作为行前总览。
- **内容：** 旅行名称、日期、城市、同行者和偏好；按日期排列的每日活动、时间、地点地址与备注；预算、参考价格和已登记实际金额；预约、住宿、应急联系人、同行需求及准备清单进度。
- **规则：** 直接汇总各模块当前数据，不另建重复记录；编辑后重新进入本页即可看到最新内容。缺失或待核实的信息明确标注，不补造路线、费用或预约结果。路线、距离和时长仅在高德返回有效结果时展示。
- **导出：** 用户可主动将当前完整旅行计划导出为 PDF 快照；文件反映生成时的最新汇总内容，中文可读并支持多页。生成失败时明确提示，不误报成功。导出文件由用户下载到本机，不上传或保存到服务端；后续修改旅行资料不会自动更新已下载文件。
- **导出内容边界：** PDF 遵循页面的敏感字段遮盖规则；不嵌入高德地图底图、POI 查询结果快照或高德实时路线/距离/时长，相关动态地图信息提示用户前往高德查看。PDF 导出不等同于旅行资料备份，不提供导入或恢复。
- **边界：** 第一版不提供其他格式导出、分享链接或自动生成/优化行程；需要修改时返回对应模块。

### 2.8 登录与注册

- **用途：** 为网站提供真实账户入口，用户注册后通过服务端验证登录并进入旅行规划。
- **功能：** 支持使用邮箱或手机号注册和登录；注册校验联系方式格式、密码规则、确认密码和账号唯一性；支持密码显隐、退出登录和会话状态保持。
- **验证规则：** 密码长度为 8–64 个字符；注册需重复输入一致。登录凭据由后端核验，服务端仅保存密码哈希。注册第一版不接邮件或短信验证码，因此不验证联系方式所有权。
- **会话规则：** 登录成功后建立有期限的安全会话；会话有效时刷新页面仍保持登录；主动退出或会话过期后需重新登录。受保护的后端 API 必须验证会话。
- **页面基准：** 双击版静态 demo 只作为视觉和通用交互样式参考；其中任意非空输入即可进入的演示登录行为不适用于正式登录逻辑。
- **边界：** 第一版不提供找回密码、联系方式验证码、第三方登录、多人协作或跨设备旅行资料同步。

## 3. 核心使用流程

1. **进入网站：** 注册新账户或使用已有邮箱/手机号和密码登录；后端验证凭据后建立会话，验证失败时留在登录页并提示。
2. **创建旅行：** 填写目的地、日期、同行者、预算和偏好。
3. **了解目的地：** 选择当前浏览城市，查看特色与美食并收藏候选内容；切换浏览城市不改变旅行目的地。
4. **安排行程：** 手动添加景点、用餐、住宿和交通，填写日期与时段，查看当天路线与交通时长。
5. **调整安排：** 手动排序、编辑备注、锁定需要保留的项目。
6. **记录购买信息：** 保存外部链接，分别填写参考价格与实际购买金额。
7. **准备出行：** 核对预约、住宿地址、联系人和清单，查看天气查询入口。
8. **核对信息：** 补齐或标记待核实的时间、地址、费用与准备事项。
9. **查看完整旅行计划：** 在汇总页按日期检查行程，并核对预算、购买信息和出行准备；需要时导出 PDF 留存。

## 4. 统一规则

### 4.1 信息与交互

| 信息类型 | 展示要求 |
| --- | --- |
| 演示内容 | 明确标记，不作为真实出行参考 |
| 外部参考 | 显示来源、适用时间与查询时间；查询时间不等于适用时间 |
| 用户填写 | 与外部核验结果区分，不能显示为网站已验证 |
| 缺失、过期或冲突 | 保留为空或标记“待核实”，提供可用查询入口 |

- 完整计划页复用六个模块的数据，清楚区分预算、参考价格与实际金额，并标注缺失或待核实项目。
- 目的地特色和城市美食页面显示当前浏览城市；切换后同步更新对应内容和地图搜索城市参数，不连带修改旅行目的地及已排日程。
- 登录与注册必须由后端验证输入和账户凭据；前端页面状态不能单独作为已登录证明。密码不得明文保存。
- 功能按钮使用对应图案并保留文字，同一操作使用一致图标。
- 无内容或保存失败时，说明原因及可用操作。
- 收藏和点击外部链接均不代表购买、预约成功或产生实际费用。
- 敏感字段默认遮盖；不因页面展示就表示真实账户权限或隐私保护已完成。

### 4.2 金额与计算

| 类型 | 含义 | 汇总规则 |
| --- | --- | --- |
| 预算金额 | 用户计划用于旅行的金额 | 用于对照，不计为实际购买 |
| 参考价格 | 查询或手动填写的预计价格 | 显示来源、时间和估算状态，不自动计入实际费用 |
| 实际购买金额 | 外部购买后由用户手动登记的金额 | 纳入实际费用，不代表已核验外部交易 |

- 以人民币元记录；参考价格和实际购买金额均填写项目总价，数量单独记录，不重复相乘。
- 实际金额未填写时保持为空，不用参考价格替代，不把未知金额写成零。
- 点击购买链接不会自动填写实际金额。
- 同一项目仅汇总一次实际金额；行程与购买信息页面关联同一份金额数据，避免重复累计。
- 展示总预算、已记录实际费用和差额；金额未补齐时提示“费用记录未完整”。修改后重新计算。

### 4.3 复用与删除

- 复用生成新旅行草稿，保留候选地点与安排参考，重新选择日期、预算和同行者。
- 不带入旧购买记录、实际支出、结清记录和敏感附件；动态资料重新核实。结清与附件能力仅在后续实现时适用。
- 删除前说明影响，并说明只影响当前浏览器数据；不声称能删除外部副本。

### 4.4 外部数据来源

- 第一版所有地图相关能力统一使用高德开放平台：地图底图展示、地点/POI 搜索与定位、地图查看/跳转、路径规划、路线距离与预计时长，以及高德地图导航。
- 城市美食中的店铺名称、地址、坐标、电话、评分与人均消费来自高德实时查询；目的地页面的地图地点查询和定位也使用高德。地图不可用或查询无结果时说明原因并提供空状态，不伪造地图/地点数据。
- 行程路线、距离与预计时长来自高德路径规划；失败时保留用户手动安排，不自动调整顺序。
- 不把高德返回的数据保存到本地或数据库、不缓存店铺照片；页面展示保留高德署名与地图标识，不脱离高德服务单独展示受平台约束的数据。
- 菜系文化、代表菜介绍、忌口与亲子筛选不属于高德地图数据，由本产品维护并按第 4.1 节标注来源与适用时间。

### 4.5 前端基准与技术栈

- **页面基准：** 纯静态双击版 [`途见-双击打开.html`](../prototype/v1/途见-双击打开.html) 是页面视觉、布局和通用导航样式基准。具体业务行为以本需求为准；S01 的注册、登录和会话流程不沿用 demo 的静态认证行为。
- **前端：** React，使用 Vite 负责开发与构建。
- **后端：** Next.js提供后端 API，不负责渲染或构建前端页面。
- **数据库：** PostgreSQL 是唯一数据库，用于正式环境的账户认证数据。
- **数据边界：** 真实账户和认证记录保存在 PostgreSQL；旅行资料按已验证账户隔离，仅保存在当前设备的当前浏览器。第一版不将旅行资料存入 PostgreSQL，不做旅行资料云端同步或跨设备同步。

| V10 | 完整旅行计划与 PDF | 能按天汇总旅行条件、活动时间与地点、费用和出行准备；修改后显示最新数据；可下载中文可读的多页 PDF 快照；敏感字段按页面规则遮盖，不包含高德地图/POI/动态路线数据；导出失败有提示；缺失与待核实信息有明确标记，不生成虚构路线或金额 |
| V11 | 浏览城市切换 | 特色和美食页面可切换城市；内容标题、列表和高德地图搜索城市同步更新，地图及地点搜索来源为高德；切换浏览城市不修改旅行目的地与已排日程；无可用资料时显示空状态 |
| V12 | 登录与注册 | 能注册并校验格式、密码规则、确认密码和账号唯一性；正确凭据才能登录，错误凭据不能进入；会话有效时刷新仍登录，退出或会话过期后需重新登录；两个账户的本地旅行资料互相隔离；桌面和手机布局均可用 |

以上清单由已确认要求整理，未增加功能范围。验收时分别记录日期、结果（通过／未通过／未验证）与证据；页面渲染通过不等于业务验收通过。

| 方向 | 保留的完整规划 |
| --- | --- |
