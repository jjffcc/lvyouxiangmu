# 目的地特色页面

日期：2026-10-04。状态：页面、特色范围、层级、内容深度与联动行为已接受；等待完整方案的共同理解确认。

## 已确认需求

为每个旅游地方增加特色介绍界面，包括但不限于人文、自然景观、美食、钓鱼、地理特色。分类可继续补充，不把这些类别限制为封闭列表。

沿用已确认的参考信息规则：来源、适用日期、查询时间；缺失、过期或冲突时标记待核实。原型使用明确标注的演示内容。

## 页面结构建议

1. 目的地概览：名称、所在区域、特色概览、图片与地图入口。
2. 分类导航：人文、自然景观、美食、钓鱼、地理特色，以及可扩展的其他分类；其中美食分类可进入独立的城市美食页面。
3. 特色列表：简要介绍、体验地点、适用季节与参考资料；根据兴趣筛选。
4. 特色详情：背景、体验方式、时间与费用参考、可核实的注意事项、来源链接。
5. 操作：收藏特色或地点、查看地图、选择关联地点后加入行程候选。

这些为可逆的页面组织建议，尚未开始界面实现。

## 各类内容建议

| 分类 | 建议字段 | 与旅行决策的关联 |
| --- | --- | --- |
| 人文 | 历史背景、地方民俗、非遗、建筑、博物馆、节庆、体验地点 | 了解背景，筛选文化体验；节庆与场馆开放时间需注明适用日期 |
| 自然景观 | 山水海岸、湖泊森林、代表景观、季节特色、游览方式、活动强度 | 匹配季节、行程时间和亲子体力要求；临时关闭或天气影响待核实 |
| 美食 | 代表菜品、小吃、食材与口味、饮食忌口、体验区域或店铺、参考费用 | 挑选用餐体验；菜品文化介绍与具体店铺当前信息分开；详细内容组织在城市美食页面 |
| 钓鱼 | 海钓或淡水等类型、体验区域、季节资料、装备与服务、费用、准入条件、预约链接 | 选择兴趣体验；具体地点是否允许钓鱼、营业、开放和费用不能凭常识默认成立 |
| 地理特色 | 地形地貌、气候特点、水系、海拔或区域位置、生态与物产 | 解释当地景观与体验特点，辅助交通、行李和体力规划；长期气候不当作当天预报 |

## 介绍、地点和活动的区别

- “当地某类美食”可以是文化特色；实际前往的餐馆应关联明确地点。
- “地形地貌”可以帮助理解当地，未必是一项可加入日程的活动。
- 钓鱼介绍不等于某个水域当前允许垂钓，也不等于已经预约到服务。
- 一项特色可以关联多个体验地点；采用城市概览和具体地方详情的分层档案，可逐层查看。

## 钓鱼资料规则

- 区分特色介绍、公开体验地点与商业体验服务，分别注明来源。
- 不默认展示未经确认的精确野钓坐标；地点准入、开放时间、季节限制和预约条件需有明确来源与适用时间。
- 无法核实时展示“待核实”和查询入口，不给出“可以直接前往垂钓”的结论。
- 商业体验提供参考信息和外部咨询、预约链接，保留禁止支付的产品边界。
- 资料来自主管部门、场地或服务方等可核实来源；AI 摘要不能替代来源证据。

## 城市美食页面（新增）

用户要求为每个城市增加独立的美食页面。它挂在“目的地特色”的美食分类下，也可从城市概览和住宿餐饮模块直达。

与特色分类的关系：特色档案中的美食品目用于“了解当地”，城市美食页面承担更完整的选餐与安排功能，包括菜系、代表菜、小吃、店铺地点、口味与忌口、营业时间、参考费用与预约参考。

### 建议内容

| 分区 | 内容 | 说明 |
| --- | --- | --- |
| 菜系与风味 | 本地菜系、口味特点、食材与代表做法 | 属于文化介绍，需注明来源 |
| 代表菜与小吃 | 菜品名称、简介、推荐吃法与适合场景 | 文化介绍与具体店铺信息分开 |
| 店铺与体验地点 | 店铺或夜市、所在区域、地标、营业时间、参考费用 | 营业时间和价格需带来源与适用时间 |
| 饮食忌口 | 辣度、素食、清真、过敏原、儿童可吃 | 与同行者的忌口偏好匹配 |
| 用餐安排 | 就餐时段、候餐时间、是否需要预约、外卖或打包 | 可关联到当日行程的时间段 |
| 操作 | 收藏、看地图、加入行程或候选、写外部预约参考 | 沿用禁止支付的边界 |

## 原型验收建议

- 展示五个指定分类和其他分类的扩展入口。
- 选择一个地方后切换分类，查看特色详情及来源状态。
- 至少演示一项仅用于背景理解的地理特色，以及一项可关联地点的体验。
- 演示钓鱼资料缺失、准入条件待核实、无该类已知特色等状态；不要用虚构事实填满每个地方的每个分类。
- 所有示例特色、地点、费用与限制均标记为演示，不作为真实出行参考。
