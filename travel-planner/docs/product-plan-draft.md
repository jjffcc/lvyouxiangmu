# 国内旅游规划产品完整方案（讨论稿）

版本：1.0（待整体确认）。日期：2026-10-04。阶段：Q1 至 Q29 已收拢，完整功能及原型交付范围等待共同理解确认；尚未开始原型实现。

## 产品目标

帮助个人自由行、情侣朋友和亲子家庭把旅行资料组织成可修改、可比较、可随身查看的行程，并在出行中管理订单、费用和变化，出行后整理照片与游记。

用户个人建设，先供本人及受邀同行者使用。中国大陆、多城市、异地往返；网页入口，蓝色视觉，手机优先且兼容电脑。外部预订跳转，禁止支付操作。

| 攻略资料 | 文字、截图、链接收藏、提取候选地点 | 提取结果需用户确认；不把未解析链接内容写成已提取事实 |
| AI 规划 | 表单和聊天入口、每日行程、多城衔接 | 先满足硬条件，再按舒适、经济、丰富节奏优化；交通和休息缓冲可调整；数据与模型实际接入待验证 |
| 行程编辑 | 拖动排序、替换、锁定、撤销、版本恢复 | 改线先展示前后、原因及费用影响，确认后应用 |
| 方案比较 | 多个行程方案的比较与选择 | 比较每日安排、交通、时间与预算，注明估算、信息缺项及硬条件冲突；展示建议见 shared-understanding.md |

| 住宿餐饮与预约 | 位置、参考资料、预订链接、预约时间 | 产品内不收款、不代付；无可靠实时价格时标注估算或待核实 |
| 订单中心 | 手动、文字、截图、PDF 导入；统一管理 | 覆盖交通、住宿、门票、餐饮预约、租车；确认后入库；重复提示 |
| 订单变化 | 手动更新取消或改期，关联行程和费用 | 确认后更新；未知截止时间待核实；退款单独记录，保留原支出与更正历史 |
| 成员与权限 | 负责人、编辑成员、只读成员、受邀分享 | 登录与跨设备同步；成员草稿、负责人发布；冲突保留双方内容；附件与联系方式独立权限，访问可撤销 |
| 预算与记账 | 往返交通、住宿、餐饮、门票、市内交通、备用金 | 全团与人均口径；估算与实际支出分开 |
| 费用分摊 | 均摊、指定成员、比例、自定义金额 | 只记录和计算费用；手动结清记录，更正后展示差额；禁止支付 |

| 离线行程 | 行程、地址、订单摘要、应急联系人 | 首版离线查看，显示版本及保存时间，联网提示更新；缓存与通知实际能力另行验证 |

| 行后回顾 | 照片、游记、评价、费用总结、行程复用 | 默认私密；可导出分享；复用时旧日期、订单和费用处理的默认建议见 shared-understanding.md |

## 主要流程

1. 创建旅行 → 输入硬性条件与偏好 → 收集候选 → 生成方案 → 对比与修改 → 确认行程。
   目的地特色页面支持收藏、查看地图和加入行程候选，提供了解当地和选择体验的入口；美食分类可进入独立的城市美食页面。
2. 查看参考信息 → 外部预订跳转 → 回到产品导入订单 → 核对确认 → 关联行程并保留预约安排。
3. 邀请同行者 → 指定角色与共享范围 → 收集偏好 → 负责人确认最终方案。
4. 出行准备 → 查看当日路线与天气 → 记录支出 → 遇到变化时查看改线建议 → 确认后应用。
5. 整理费用、照片与游记 → 导出或受邀分享 → 复用行程。

## 不能混淆的信息

- 演示内容、预算估算、外部参考信息、用户确认信息和待核实信息分别标记。
- 查询时间不等于数据适用时间；订单记录更新时间不等于外部订单核验时间。
- 费用分摊不等于实际转账，预订链接不等于已经预订。
- 原型的演示登录、邀请、AI、导入识别及同步不能被描述为已接入的真实服务。

## 原型交付与后续正式接入

首先制作本地可点击网页原型，覆盖上述全部功能入口和主要流程，采用明确标注的演示数据，蓝色、手机优先、兼容电脑。账户、同步、AI、OCR、权限和天气等外部能力在原型阶段可用演示流程表达；不得把演示通过报告为真实接入完成。

真实数据服务、账户权限、跨设备协作、模型、OCR、通知和离线能力属于后续可用网站的接入与验证工作；具体供应商、费用和部署方式在接入时根据实际条件决定。需要付费时再讨论，暂不设固定上线日期。

Q1 至 Q29 的选择已记录，剩余一步是用户确认整份共同理解。原型组织和少量补充默认规则列在 shared-understanding.md，尚未被单独批准的内容已明确标记，随整体方案一并审阅。
